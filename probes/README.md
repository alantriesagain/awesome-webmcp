# scriptc probes

One-file programs that decide design branches. `npm run probes` rebuilds every probe natively,
runs it, diffs the output against Node and writes `RESULTS.md`. Decisions taken from the
2026-10-12 run (scriptc 0.2.9):

| Probe | Outcome | Decision |
|---|---|---|
| p0 function members in a union | FAIL (SC2003/SC2020) | Thunks and handlers are boxed: `Live`, `Handler` classes. No raw arrows in templates. |
| p2 (run by hand on apps/desktop) the desktop app importing light's desktop host by name: `@lightstart/light/native/desktop` (an export with `types` and `default` conditions), `@lightstart/light/native/desktop/index.ts` (the `./*` route) with `export *` and with named re-exports | FAIL: the bare route takes the TypeScript entry as program source but not the JavaScript host behind it (`host.js`, `window.js`, `server.js`, `init.js`: `DesktopWindow` is not a class declared in the program, 344 to 491 of 757 statements analysed); the relative route through the root's `light` link is fully static (757 statements) | The desktop app imports the host by relative path through the workspace's `light` link until light's desktop host is TypeScript; every other import of light in the workspace is bare. |
| p1 / p9 / p11 recursive `V \| V[]` union | compiles "fully static" but **miscompiles** nested arrays (garbage output, segfault, RangeError) | The template value type is **non-recursive**: `type Item = …; type Value = Item \| Item[]`. Lists of lists are a type error. |
| p10 non-recursive value shape | PASS | Adopted (classes with fields typed as the union, `fn: () => Value`, map-produced lists all work). |
| p2 signals graph (abstract Reactive, `Set<Reactive>`, generic `Signal<T>`, `Computed<T>` getter override) | PASS | Signals package mirrors this probe. |
| p3 discriminated record union in a class field | PASS | `ChildPart.state` is a record union holding class refs. |
| p4 `Map<TemplateStringsArray, Class>` | PASS | Per-call-site template cache. |
| p5 relative `.ts` imports across directories | PASS | Packages are directories; all imports relative. |
| p6 `(() => void) \| null` field, arrays of functions, Set/Map of instances | PASS | Listener arrays; `Emitter<T>`. |
| p7 JSON partial casts | PASS (extra keys ignored at every level; mismatched types throw `TypeError` natively, Node does not check) | Envelope decoding = parse to `unknown`, narrow partial casts. |
| p8 `Intl.Segmenter`, typed arrays, microtask/immediate/timeout order | PASS | Renderer building blocks available. |

| p12 `(Item \| Item[])[]` as a rest parameter and literal | PASS | `html(strings, ...values: Value[])` with `${items.map(…)}` works. |
| p13 / p14 / p15 template commit segfault | native segfault / wrong dispatch | Led to p16/p17. |
| p16 which union arm breaks dispatch | every variant with an array arm fails | Not an arm problem: a pattern problem (see p17). |
| p17 `instanceof` on a union with an array arm | **direct `instanceof` returns false natively**, and so does `instanceof` after an inline `Array.isArray` narrowing in the same function (and in a ternary). Only `Array.isArray`, then a call to a function whose parameter is typed `Item`, dispatches correctly. A statically-decided `instanceof` (exhausted union) or `Array.isArray` on a known non-array is a compile error (SC1090). | Rule: split `Value` with `Array.isArray`, pass the item to a function typed `Item`, never test the last arm of a union. `parts.ts` follows this. |

| p22 / p23 / p28 / p29 / p31 `input.changed.emit is not a function` natively | The call fails only in programs that also link a class with a **function-typed field named `emit`** (`InputDecoder.emit`), while `Emitter` has a *method* `emit`. Same-name field/method across unrelated classes miscompiles the method call. | Rule: a function-typed field must not share its name with any method anywhere in the program. Renamed `InputDecoder.emit` → `deliver`, `ComputedNode.invalidate` → `onInvalidate`. |

| p36 a program importing `tdom/index.ts` that holds a never-awaited Promise-returning function | **link error** natively (scriptc fork 0.3.1, and still on 0.3.2): `undefined reference to scr_dyn_new_promise_adapting`; the runtime pack has it in `scr_async_dyn.o`, which the linker does not select | Keep pure models (apps/widecode `tree.ts`) out of modules that import light; to report upstream with this probe. |

| p37 parsed JSON kept alive | parsing a real 4 MB transcript window natively: 9 ms with each result dropped, 267 ms with all kept (superlinear in the live set), 573 ms for a second pass beside the first; node 18 ms | Keep transcript lines as text; parse a record only while applying it; keep typed extracts (a patch's hunks), not parsed results. Resume + first paint of the bootstrapp session went from ~400 ms to 57 ms. |

| p39 object literals with the same keys in different orders | natively `JSON.stringify` writes each in the **first** literal's key order (they share a layout), still on 0.3.2; node keeps each literal's own order | Never depend on the key order of `JSON.stringify` output from literals; write fixed text when order matters (tests that build JSONL records). To report upstream. |

| p40 QuickJS inside a scriptc binary (`scriptc run --ffi apps/widecode/native/ffi.json probes/p40-quickjs.ts`, native only) | PASS once quickjs-ng is built apart: scriptc's runtime links its own copy of QuickJS's regex and Unicode code, and both define the hooks libregexp calls (`lre_realloc`, `lre_check_timeout`, `lre_check_stack_overflow`); the prebuilt `libscriptc-quickjs.a` would collide on 35 symbols. `apps/widecode/native/build.sh` renames this copy's 44 exported regex, Unicode and number symbols `qjs_*` (zero shared after). Evaluation, Unicode strings, a plugin's call into the host answered by `wcjs_reply` (a host error thrown in JS), the host invoking a plugin function, a host call calling back into JS, promise jobs, an error's stack, a runaway loop stopped by the 250 ms budget, out of memory as an error, the engine usable after each. 10k host-to-JS calls with JSON both ways: 14 ms; 10k JS-to-host calls: 5 ms. The engine adds 1.27 MB to a stripped binary (libc and libm dynamic, as before). | widecode's plugins run in this engine (the plan's phase 0 gate). FFI cannot return strings: results come back through call-scoped callbacks, a host call's answer through `wcjs_reply`. |

| p41 an HTTP server on 127.0.0.1 at a port the system picks (node:http in the same program as its client): a JSON body answered with JSON, a response held open and written as an event stream in parts while a timer runs, a request refused for its token, the server closed | PASS, fully static (`res.end(JSON.stringify(...))` is refused, SC2020: the argument must be a plain `string`, so it goes through `"" + JSON.stringify(...)`) | widecode's MCP server (`apps/widecode/src/services/mcp.ts`). |
| p42 a generic class with methods and no function field (`Keyed<T>`: parallel arrays, `put`/`get`/`removeOwner`/`values`) beside light's template engine, its items dispatched through `T` | PASS (fully static, outputs equal) | `Keyed<T>` in `src/kernel/registry.ts` holds the kernel's registries (commands, actions, key layers) and the screen's segments. |
| p0 (`p0-workspace/`) a pnpm workspace with `light` a symlinked member, a `@tui/*` package whose exports name `.ts` files, a package holding an FFI manifest with its archive under its own folder, and an app importing all of them by name (`@lightstart/light/native`, `@lightstart/light/controller/class.ts`, `@tui/probe-lib`, `@tui/probe-lib/lines.ts`) | PASS: coverage fully static (3828 statements), `scriptc build` and `scriptc run` print what node prints, the FFI archive links through the symlinked manifest path and through its realpath, a test run from the app's folder reads a cwd-relative fixture under both runtimes (scriptc 0.3.6 fork, light with `native/index.ts`) | The workspace imports light and the packages by name: a bare import landing on a `.ts` file of a package linked by symlink compiles as program source; one landing on `.js` is judged an npm package, so light's native entry is `index.ts`. The desktop route the same way: with light's `./native/desktop` export one `.ts` entry (its values and types), the desktop app imports the host by name and builds through light's desktop shell. |

Keep the failing probes: they document compiler behaviour and should be re-run on every scriptc upgrade.
