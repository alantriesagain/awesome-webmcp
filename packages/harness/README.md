# @widecode/harness

widecode's own coding agent, the harness: a daemon of widecode's binary (`widecode --harness`) that speaks ACP over stdio to the app's ACP plugin, talks to model APIs directly, runs its own tools and keeps its own sessions. The plan is in the repository's `PLAN.md`, milestone J; this README grows with the slices.

| File | Role |
|---|---|
| `cli.ts` | `harnessMain`: the daemon on stdio, its log under the store's `harness/logs`, the side commands the ACP entry runs (`--harness-tools <mode>`, `--harness-skills`, `--harness-sessions`, `--harness-forget <id>`), and the user's (`--harness-models`, `--harness-auth <provider>`: a key read from stdin into `~/.widecode/auth.json`, readable by the user alone) |
| `main.ts` | the same under node, for the app's tests (`node packages/harness/main.ts --harness ...`) |
| `acp/server.ts` | JSON-RPC 2.0 over stdin and stdout: requests, notifications, responses, the client's ids echoed as they came, a trace file (`--log`) |
| `acp/agent.ts` | the methods over the sessions: initialize, session/new, load (a session this process does not hold is read from its file and its turns shown again before the answer), resume (no replay), fork (the branch copied into a file of its own), prompt (a prompt mid-turn steers the turn and is answered with it; `/title [words]` names the session), cancel, set_config_option, list (the folder's files); `_meta.widecode` (the project's prompt and trust) kept per session; after the first turn a cheap model of the provider names the session |
| `acp/options.ts`, `acp/updates.ts` | the config options (model, effort, mode) and the `session/update` texts (chunks, usage, commands, options, mode) |
| `loop/` | the agent loop (a turn's requests until the model stops, tool batches between them: one call at a time when one mutates, together otherwise, the results in one message, synthetic ones after a cancel; steering between requests), its listener, the abort; `compact.ts`, compaction in pi's shape (past the threshold, the window less a reserve or the config's `compactAt`, the messages before the last 20,000 tokens are summarized by the model into a fixed structure, the summary sent as the first user message from then on; `/compact [hint]` summarizes everything so far); `tokens.ts`, the estimate (four characters a token, corrected by the last request's count) |
| `model/` | the neutral message shape (parts: text, thinking with its signature, tool call, tool result, image); `client.ts` dispatching by the model's API; `openai.ts`, an OpenAI-compatible chat completions API (tool calls and their results as tool messages, a reasoning model's `reasoning_content` read and sent back on the assistant's messages, which DeepSeek and Kimi require with tools, thinking toggled or an effort by the model's kind, the cached share of the usage); `anthropic.ts`, the Anthropic Messages API as JSON text and its events read (thinking by the model's kind, Anthropic's extras for providers that take them: cache breakpoints, eager input streaming, the effort; a refusal or an error as the stream's end; 429, 529 and server errors tried again before anything streamed); `sse.ts`; `registry.ts`, the providers (Anthropic; DeepSeek through its Anthropic-format endpoint) and models with windows, prices, thinking kinds and efforts; the fake client scripted from a JSONL fixture (text, thinking, tool calls, a hold, an error) |
| `http/stream.ts` | a streaming request behind one class, by `node` (http and https requests with per-chunk data events) or `curl` (`-N -i`, the body on stdin), chosen by the config's `http`; an idle timer, an abort |
| `tools/` | the tools, named as Claude Code names them: `Read` (numbered lines, offset and limit, caps; what it read may be edited), `Write` (a whole file, its folders made, refused for an unread file), `Edit` (an exact unique string replaced, or every occurrence; CRLF, BOM and the mode kept; the patch with line numbers as the result), `Bash` (a command in the folder through `proc.ts`, output capped to its start and end, a timeout, killed on abort), `Grep` (ripgrep when on PATH, else grep), `Glob` (the workspace's file list, newest first), `LS`, `Skill` (a skill's instructions by name), `permissions.ts` (the calls `permissions.deny` refuses, the user's config's and a trusted project's, in Claude Code's syntax: Bash patterns over each simple command, gitignore-style paths for Read and Edit, WebFetch domains, tools and MCP servers whole; a refused call ends with its rule), `WebFetch` and `WebSearch` (`web.ts`: a page through the browser, else curl, as markdown cut at 50,000 characters; a search over the backends in order until one gives results: SearXNG when `harness.search.searxng` names an instance, Google through the browser, Brave's and Tavily's APIs with a key, DuckDuckGo's HTML page only when `harness.search.order` lists it); `browser.ts`, headless Chromium (the config's `harness.browser.command`, else Playwright's headless shell or Chromium under `~/.cache/ms-playwright`, else one on PATH) run once per page with a fresh profile under the store, its DOM printed after the scripts ran; `html.ts`, a page's HTML as markdown (its main content, links resolved); `mcp.ts`, the MCP servers the client gives a session (widecode's own over HTTP with its token): their tools listed when the session opens, offered as `mcp__<server>__<tool>` and titled `<server>_<tool>` for the client, a call read to the end of its event stream and dropped on abort; `patch.ts`, the Myers line diff and the unified patch the code column follows; the set of a mode (plan mode's read-only share), the tools' JSON for the API, an input checked against its schema before it runs |
| `session/` | a session's file under `~/.widecode/harness/sessions/<folder key>/<id>.jsonl` in pi's shape (`entries.ts`: a header line, then entries with `id` and `parentId`, the branch the walk back from the last one: a message with its parts, a model or mode change, a title, a compaction); `store.ts`, the files: made on the first entry (a session never written leaves nothing), appended to, loaded as the branch, listed through the header and the tail (the last title), forked as a copy, removed; a tool result keeps its outcome as JSON, which `replay.ts` turns back into completed calls with their diffs when a load shows the turns again, paced; `title.ts`, the session's title asked of the provider's cheapest model with the agent package's naming prompt |
| `prompt/` | the system prompt (`system.ts`): stable blocks first, cached where the provider caches (the base text with how to use the tools, the folder and platform, the project's text from the client, the project's instructions, the skills), then a small block that changes (the date, plan mode's note) sent last and uncached; `context-files.ts`, AGENTS.md, CLAUDE.md and .claude/CLAUDE.md from the repository's root down to the folder (a trusted folder's), then `~/.widecode/harness/AGENTS.md`, cut at 32 KB a file and 128 KB in all, a file with another's text left out; `skills.ts`, the skills in the Agent Skills format from the folder's `.agents/skills` and `.claude/skills` (trusted), the user's `~/.agents/skills`, `~/.claude/skills` and its synced folders, and `~/.widecode/harness/skills`, listed by name and description (`disable-model-invocation` keeps one out of the prompt) |
| `auth.ts` | the keys: the provider's environment variable, else `auth.json` |
| `config.ts`, `paths.ts` | the `harness` section of config.json (`model`, `effort`, `compactAt`, `http`, `providers` with their models, prices and thinking kind); where the harness keeps its files |

Google refuses searches from a fresh headless profile as unusual traffic on some machines; SearXNG (`docker run -p 8080:8080 searxng/searxng`, with `json` in its `search.formats`) or a key (`widecode --harness-auth brave`, `widecode --harness-auth tavily`, or `BRAVE_API_KEY`, `TAVILY_API_KEY`) searches without that.

## The benchmark

`bench/` measures agents on real models: eight small tasks, two of them harder (an RFC 4180 parser, a concurrency limit) (`bench/tasks/<name>/`: a repository, a
prompt, a check the agent never sees, and a solution the test checks the check against), run over
ACP, so the harness, opencode and the DeepSeek Harness are measured alike. A run copies the task
into a temp git repository, starts the agent there, chooses the model and effort through the
session's options, sends the prompt, follows the turn (cancelled past the task's time), runs the
check, and deletes the session. It records the time to the first token and in all, the calls by
tool and those that failed, the tokens, the context and the cost the agent reported; the records go
to `bench/results/` (ignored by git) and a table is printed.

```
node packages/harness/bench/run.ts --model deepseek/deepseek-flash,opencode/kimi-k2.6 --repeat 2 --budget 1
node packages/harness/bench/run.ts --agent opencode --model opencode/big-pickle --tasks fix-bug,edit-json
node packages/harness/bench/run.ts --report packages/harness/bench/results/*.jsonl
```

It talks to real models and spends real money; `--budget` stops starting runs once the reported
cost passes it. `test/bench.test.ts` runs it on the fake model.

The entry in config.json is a default of the ACP plugin, chosen with `"agent": "harness"` or `--agent harness`. A key: `DEEPSEEK_API_KEY` or `ANTHROPIC_API_KEY` in the environment, or `widecode --harness-auth deepseek` with the key on stdin. Tests: `light-native test harness` (the ACP framing, the agent over the fake model with a tool batch, its session file, a load in another process and a resume, the Anthropic request and its events, the HTTP stream by both ways against `test/fake-model.mjs`, the tools over a temp folder, the session store and the replay, the registry, costs and keys); the app's `test/harness-agent.test.ts` drives the daemon under node as the fake agent is driven, the Sessions tab and a side question's fork included.
