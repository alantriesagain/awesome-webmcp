# @widecode/conversation

A conversation with a coding agent, with nothing of one agent or one app in it. `model.ts` is the `ChatModel`: turns of items (text, thinking, tool calls with their results, subagents, notices, prompts), the queue of pending messages, a version signal the views follow. `events.ts` applies the neutral events an agent adapter sends (`api.conversation.apply` in widecode) to the model and the status. `conversation.ts` is the `Conversation`: the model, the `Agent` it talks to (`agent.ts`, the role an adapter subclasses), the folder it works in, the session it resumes, the requests it holds for the user (`requests.ts`), and the records it keeps through a `SessionStore` (`session-store.ts`: a session's record and the account's limits, held by the app's store). `status-info.ts` is the status line's data in Claude Code's statusline shape; `activity.ts`, `agents.ts`, `calls.ts` and `skills.ts` say what the agent is doing, which subagents ran, what a call's state is and how each skill it loaded ran on; `command.ts` says what a shell command runs (its segments and their programs, `git status`, `pnpm install`), for a call's line and the Available tab's counts. `render.ts` draws the model's items as terminal lines (through `@light/markdown`) and `model-source.ts` is the `LineSource` the panes build on, rebuilt when the model, its version or the width changes. `attach.ts` turns `@path` images in a message into blocks; `history.ts` keeps the folder's messages for the composer's walk.

Tests: `test/history.test.ts` and `test/command.test.ts` (`light-native test conversation`); the model and rendering are proven by widecode's tests over recorded sessions.
